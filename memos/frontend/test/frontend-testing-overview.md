## UIコンポーネントテスト

Testing Library等を使い、コンポーネントをレンダリングしてDOM上の挙動を検証するテスト。
jsdom（DOMをjsでエミュレートした実装）を使う。

### ポイント

実装の詳細ではなく、ユーザーから見える挙動（表示されるテキスト・要素の状態）を検証する。

## Storybook Play Function

実際のブラウザエンジンを使う。

開発者が挙動を目視で確認できる。
CSSの影響を受ける要素の挙動や、実際のWeb APIを使ったテストが書ける。
VRTと連携した見た目の差分検知。

実行時間がかかるため、対象を絞る。

## VRT（Visual Regression Testing）

スタイル崩れが起きやすい、または見た目の担保が重要なコンポーネントに対して使う。
金銭的コストがかかる。

## E2E

実際のユーザーフローをブラウザ上で通しで検証するテスト。

決済・認証など、失敗した際の影響が大きい重要なユーザーフローに絞る。

### ポイント

実行コストが高く壊れやすいため、広範囲をE2Eでカバーしようとしない。
