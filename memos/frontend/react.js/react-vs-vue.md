# ReactとVueの比較

## 宣言的UI

ReactもVueも宣言的UI。jQueryは命令型のDOM操作ライブラリ。
宣言的UIの場合は、状態に紐づくDOMの更新は自動で行われる。
命令型の場合は、状態に紐づくDOMの更新をすべて書く必要がある。

## 設計思想

Reactはsimple, Vueはeasy。

## リアクティビティの仕組み

Reactは仮想DOMのdiffingで動く。
状態が変わるとコンポーネント関数が再実行され、返された要素木を前回のものと比較して、差分だけDOMに反映する。
再レンダリングは子孫コンポーネントにも波及するため、`memo` / `useMemo` / `useCallback` で明示的に止める必要がある。

開発者の責務は次の3つ。

- 子コンポーネントの再レンダリング: 親が再レンダリングされると、propsが変わっていなくても
  子は再レンダリングされる。`memo`でコンポーネントをラップすると、propsが（浅い比較で）
  変わっていない限り再レンダリングをスキップできる。
  Vueは子コンポーネントが自分の依存しているリアクティブ値だけを追跡するため、
  `memo`に相当する明示的な対処が不要。
- オブジェクト・配列・関数の再生成: JSXで`<Child data={{ a: 1 }} />`のように書くと、
  親が再レンダリングされるたびに新しいオブジェクトが作られる。`memo`は浅い比較なので、
  中身が同じでも参照が変われば「propsが変わった」と判定されてしまう。
  これを防ぐために`useMemo`（値の再生成を防ぐ）、`useCallback`（関数の再生成を防ぐ）で
  メモ化する。
  Vueは参照ではなく値へのアクセスを追跡するため、オブジェクトの参照が毎回変わっても
  中身が変わっていなければ再レンダリングは起きない。
- 依存配列の管理: `useMemo(() => f(a, b), [a, b])`や`useEffect(() => {...}, [a, b])`の
  第2引数は、開発者が手で列挙する。列挙漏れは古い値を参照し続けるバグ（stale closure）になり、
  不要な値を入れると意図せず頻繁に再計算・再実行される。
  Vueの`computed`はアクセスされた値から自動で依存を検出するため、依存配列を書く必要がない。

Vueはリアクティブシステムで動く。
`ref` / `reactive` でラップした値へのアクセスを Proxy（Vue 3）経由で追跡し、その値に依存しているレンダリング関数だけを再実行する。
再レンダリング範囲は依存関係から自動的に絞られるため、Reactのmemo化に相当する作業が基本的に不要。

## 記法

ReactはJSX。JavaScriptをそのまま書ける。
Vueはディレクティブなど、独自の記法を覚える必要がある。
Composition API もあるが、結局はReactの後追い。
