# Evaluator-Optimizer パターン

Anthropic「Building effective agents」で紹介されているワークフローパターン。
成果物を作る役と評価する役を分け、評価のフィードバックを受けた改善を繰り返して品質を上げる。

仕組み:

- generator が成果物を出す
- evaluator が基準に沿って評価し、フィードバックを返す
- generator がフィードバックで改善する
- 基準を満たすまでこれを繰り返す

evaluator は成果物を作らず、評価だけを担当する。

向くタスク:

- 評価基準が明確
- 反復で品質が上がる
- 例:
  - 翻訳の推敲
  - コードレビュー
  - 設計書・ADR の推敲（基準をチェックリスト化できる場合）
  - SQL のチューニング（`EXPLAIN` の結果を基準に、目標のコストや実行時間を満たすまで直す）
  - 実装の修正（テスト・lint・型チェックの結果を評価にして、全て通るまで直す）

## Claude Code での実装方針

skill と sub-agent を組み合わせる。

役割分担:

- evaluator は sub-agent にする
  - 評価基準はプロンプトに書く
  - generator の思考過程が見えない別コンテキストで評価できるので、自分の成果物に甘くなるのを避けられる
- generator はメインセッションか別の sub-agent にする
  - 実装内容が会話の文脈に依存するなら、メインセッションが扱いやすい
- ループ制御は skill に書く
  - 手順は「生成 → evaluator を呼ぶ → 基準未達なら指摘を渡して再生成 → 基準を満たすか上限回数で終了」

実装時の注意:

- 終了条件を必ず決める。基準は数値かチェックリストで書き、最大反復回数も決める。決めないと無限ループやトークンの浪費になる
- evaluator の出力形式を固定する（例: 合否と、修正が必要な点の箇条書き）。skill 側が合否を機械的に判定できる
