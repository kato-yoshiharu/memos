# AIの開発ワークフローの学習ログ

<https://zenn.dev/avaintelligence/articles/dont-outsource-understanding-to-ai>
「AIに丸投げしないで理解するためのAI開発手法（2026年8月現在）」（2026-08-28公開）のメモ。

AIに丸投げすると、技術負債と理解負債が溜まる。

grill-with-docsを使っている。grillingとの違いをあとで調べる。
explain-visuallyは視覚的にわかりやすく説明させるためのskillのよう。便利そう。

## ワークフロー

1. grill-with-docsでIssueの要件を対話で詰める
2. Claude Codeで実装計画を作る
   - この記事に実装計画のテンプレートがあるので、実際に実装計画を作成する際に参考にしようと思う
   - 別セッションのAIが単体で実装できる内容にする
3. explain-visually（筆者自作）で計画を読む
4. Codex（GPT-6 Astra）で実装計画のレビューループを行う
   - codex-plan-review-loop skillを自作している。これを自分でも自作する。
   - `計画の穴を発見するという能力に関しては、このモデルが最も優れている`らしい
   - `通常では想定する必要のないレアケースや過剰なまでの防御的なコードを要求してくる悪癖`もあるらしい
   - 実装計画を理解していないと、AIの間違ったレビュー指摘を弾けない
5. 新しいセッションで実装する
   - > Cursor上だとパソコンを閉じても実装が動き続けるので、昼間に計画作りをして夜はCursorのCloud上で実装というスタイルが多いです。
     - へー使ってみる
   - > Grok 4.6でExtra Highで実装することが多い。ローカルで実装する場合はGPT-6 Astra
6. 実装計画作成とは別のモデルでPRをレビューする
   - codex-pr-review-loop skill を自作している
7. 人間が最終確認してマージする
